DuskBloom Center v0.7.3 — How Updates Work

There are TWO different kinds of updates:

1) COMPONENT UPDATE
Example: DuskBloom Screen 3.4.4 -> 3.4.5, or DuskBloom Web 1.1 -> 1.2.

A. Build the new component and make a ZIP.
B. Put that ZIP somewhere your users can download with a direct HTTPS URL.
   GitHub Releases is a good eventual home for DuskBloom release files.
C. Open update_catalog.json.
D. Change that component's "version" to the new version.
E. Change its "url" to the direct downloadable ZIP URL.
F. Publish the updated update_catalog.json at the catalog URL Center checks.
G. Center compares installed/bundled versions to the catalog and offers Update.

Example:
"web": {
  "version": "1.2.0",
  "url": "https://YOUR-HOST/DuskBloom_Web_v1.2.zip",
  "notes": "Improved Canvas support"
}

2) CENTER UPDATE
Example: Center 0.7.3 -> 0.9.0.

A. Build the new Center.
B. ZIP the finished Center release.
C. Upload that ZIP to your update host.
D. In update_catalog.json change center.version and center.url.
E. Publish the new catalog.
F. Existing copies of Center see that a newer Center version exists.

IMPORTANT
The current catalog in this development build is bundled locally. A local catalog
is useful for testing, but copies already given to friends cannot learn about a
new local file on your PC. For real automatic updates, Center needs ONE stable
online catalog URL. Then you only update that online JSON whenever you release
something.

Recommended release structure:
releases/
  update_catalog.json
  DuskBloomCenter_v0.9.1.zip
  DuskBloomScreen_v3.4.5.zip
  DuskBloomWeb_v1.2.0.zip

For DuskBloom Web specifically:
Updating the files Center stores is separate from installing an unsigned
temporary extension into Zen/Firefox. Center now labels that state honestly.
A signed Firefox/Zen extension is needed for normal persistent browser installs
and browser-managed extension updates.
